Interfacing HC-05 Bluetooth Module with Arduino

1. Introduction and learning objectives

The HC-05 is a low-cost Bluetooth Classic module commonly used to add short-range wireless serial communication to microcontroller projects. It provides a UART (Universal Asynchronous Receiver/Transmitter) interface: bytes received over Bluetooth are delivered on its serial pins, and bytes sent by the Arduino can be transmitted wirelessly to a paired device.

Core idea: the HC-05 acts as a wireless serial cable. Your Arduino sketch reads and writes serial bytes; the Bluetooth link carries those bytes between paired devices.

Learning objectives

  • Identify HC-05 power and UART pins.
  • Wire the module safely to Arduino Uno.
  • Understand UART and Bluetooth pairing.
  • Upload a sketch and exchange text.
  • Diagnose common connection failures.

Prerequisites

  • Basic Arduino IDE use
  • Digital pins and serial communication
  • Voltage, current, ground reference
  • Basic C/C++ sketch structure

Key terminology

UART: asynchronous serial interface.

Baud rate: symbols per second; commonly 9600 for data mode.

Pairing: establishing a Bluetooth relationship.

TX/RX: transmit and receive data pins.

What the project demonstrates

After pairing a phone or computer with the HC-05, a Bluetooth serial-terminal app can send a character such as 1 or 0. The Arduino receives it and prints a response. The example below demonstrates communication only; it does not switch a high-power load.

3. Circuit diagram and wiring

This illustrative circuit uses SoftwareSerial on Arduino pins D10 (RX) and D11 (TX), leaving the Uno's USB serial pins D0/D1 available for uploading and the Serial Monitor.

Wiring summary
HC-05 TXD → Arduino D10
Arduino D11 → 1 kΩ resistor → HC-05 RXD; HC-05 RXD node → 2 kΩ resistor → GND (approx. 3.3 V from a 5 V output)
HC-05 GND ↔ Arduino GND
HC-05 VCC → a supply compatible with your particular board

Voltage-divider calculation

Vout = Vin × Rbottom / (Rtop + Rbottom)

With 5 V input, Rtop = 1 kΩ and Rbottom = 2 kΩ: Vout = 5 × 2/(1+2) ≈ 3.33 V. This reduces the logic-high voltage before it reaches HC-05 RXD.

4. Working principle

  1. Power-up: the HC-05 powers on and its LED indicates its current status. Blink patterns vary by module and firmware.
  2. Pairing: enable Bluetooth on a phone/PC, scan for the module (often named HC-05), and pair. Common default PINs on some modules are 1234 or 0000; yours may differ.
  3. Wireless-to-UART path: characters sent by the terminal app cross the Bluetooth connection and appear at HC-05 TXD. Arduino reads them on D10.
  4. UART-to-wireless path: bytes written by Arduino on D11 reach HC-05 RXD through the divider, then are transmitted to the paired terminal.
  5. Baud-rate match: the sketch uses 9600 baud for the HC-05 data UART. Both ends of the serial link must use compatible settings.

Advantages and limitations

Advantages

  • Low cost and widely used in student prototypes
  • Wireless control without a data cable
  • Simple UART interface
  • Useful for telemetry and short-range control

Limitations

  • HC-05 is Bluetooth Classic, not BLE
  • Range and reliability depend on environment and antenna
  • Not intended for internet access directly
  • Logic-level and supply details vary by board
  • Phone OS/app compatibility may differ
Common misconception: HC-05 is not a Wi-Fi module and does not provide internet connectivity. It is a short-range Bluetooth serial bridge.

5. Arduino program

Upload this sketch to an Arduino Uno. It uses D10/D11 for HC-05 and the USB serial connection for debugging. The sketch echoes received text to the Bluetooth terminal and accepts 1 or 0 as example commands.

#include <SoftwareSerial.h>

// Arduino RX, TX
SoftwareSerial BT(10, 11);

const int ledPin = LED_BUILTIN;

void setup() {
  pinMode(ledPin, OUTPUT);
  Serial.begin(9600);  // USB Serial Monitor
  BT.begin(9600);      // HC-05 data-mode UART (typical default)
  Serial.println("HC-05 ready. Pair your phone and send text.");
  BT.println("Connected to Arduino!");
}

void loop() {
  // Data arriving from phone -> HC-05 -> Arduino
  while (BT.available()) {
    char c = BT.read();
    Serial.write(c);       // show received byte on computer

    if (c == '1') {
      digitalWrite(ledPin, HIGH);
      BT.println("\\r\\nLED ON");
    } else if (c == '0') {
      digitalWrite(ledPin, LOW);
      BT.println("\\r\\nLED OFF");
    } else if (c == '\\r' || c == '\\n') {
      // Ignore terminal line endings
    } else {
      BT.write(c);          // echo other characters back
    }
  }

  // Optional: computer Serial Monitor -> phone via HC-05
  while (Serial.available()) {
    BT.write(Serial.read());
  }
}
How to use the sketch
  1. In Arduino IDE, select the correct board and COM/serial port.
  2. Upload with the HC-05 connected as shown. If upload fails, temporarily disconnect wires from D0/D1 if used by any circuit.
  3. Open Serial Monitor at 9600 baud.
  4. Pair the phone with HC-05 and open a Bluetooth Classic serial terminal app.
  5. Send 1 to turn on the Uno's built-in LED; send 0 to turn it off.

Program logic in plain language

  • SoftwareSerial BT(10, 11) declares Arduino D10 as receive and D11 as transmit.
  • BT.begin(9600) sets the module's data UART speed for this example.
  • BT.available() checks whether received bytes are waiting.
  • BT.read() reads one byte; BT.write() transmits a byte without text formatting.
  • BT.println() sends text followed by a line ending.
The HC-05's UART baud rate in data mode is often 9600, but not guaranteed for every configured module. AT-command mode uses different procedures and commonly different baud settings. Do not assume the data-mode rate and AT-mode rate are identical.

6. Practical procedure, observations and troubleshooting

Lab procedure

  1. Inspect the HC-05 board and confirm its power-input rating and pin labels.
  2. Build the circuit with power disconnected; double-check TX/RX crossing and the divider.
  3. Connect common ground and then power the circuit.
  4. Upload the sketch and confirm the IDE reports a successful upload.
  5. Pair the phone/PC with HC-05. If prompted, try the PIN supplied with the module or its documentation.
  6. Open a Bluetooth serial terminal, connect, and send 1, 0, and ordinary text.
  7. Record whether the LED responds and whether received/transmitted text appears as expected.

7. Solved numerical examples

Example 1 — Voltage divider (easy)

Given: Arduino output = 5 V, Rtop = 1 kΩ, Rbottom = 2 kΩ. Find the voltage delivered to HC-05 RXD.

Formula: Vout = Vin × Rbottom/(Rtop + Rbottom)

Substitution: Vout = 5 × 2/(1 + 2) = 10/3 = 3.33 V.

Answer: approximately 3.33 V, a reduced logic-high level suitable for a typical 3.3 V UART input, subject to the module's specification.

Example 2 — UART byte time (moderate)

Given: UART setting 9600 baud, 8 data bits, no parity, 1 stop bit (8-N-1). Find approximate time for one byte frame.

Each frame uses 1 start + 8 data + 1 stop = 10 bits. At 9600 bits/s, time = 10/9600 s = 0.0010417 s.

Answer: approximately 1.04 ms per byte, excluding software overhead and Bluetooth packet/link delays.

Example 3 — Divider current (moderate)

Given: 5 V source and series resistors 1 kΩ + 2 kΩ. Approximate current through the divider, ignoring the HC-05 input load.

I = V/Rtotal = 5 V / 3000 Ω = 0.001667 A.

Answer: approximately 1.67 mA. This is an ideal estimate; actual input loading and output resistance affect the result.

Example 4 — GATE-style baud calculation (difficult)

Question: A UART sends 100 bytes using 8-N-1 framing at 9600 bit/s. Ignoring inter-frame gaps and Bluetooth overhead, estimate the minimum serial transmission time.

Each byte requires 10 bits, so 100 bytes require 100 × 10 = 1000 bits. Time = 1000/9600 = 0.10417 s.

Answer: approximately 104 ms. Actual end-to-end Bluetooth delivery may take longer because this estimate excludes protocol overhead, buffering and application delays.

9. Core electronics / embedded interview questions

1. What is the HC-05 module?

A Bluetooth Classic module commonly used to provide a wireless serial link through UART TXD and RXD pins.

2. How is HC-05 different from HC-06?

Common HC-05 boards can support master and slave roles depending on firmware/configuration, while common HC-06 boards are typically slave-only. Clone variants exist, so confirm the exact board.

3. Why do TX and RX need to be crossed?

Data output from one device must reach the input of the other. Connect HC-05 TXD to Arduino RX, and Arduino TX to HC-05 RXD.

4. Why use a voltage divider?

To reduce the Arduino Uno's 5 V TX logic to a level closer to the HC-05's typical 3.3 V UART input level. A logic-level shifter is another option.

5. What does baud rate mean?

It describes the signaling rate. For the common binary UART configuration, baud rate corresponds to bit rate. Both serial endpoints must use compatible settings.

6. What is the purpose of SoftwareSerial?

It implements serial communication on selected digital pins in software, allowing the Uno's hardware UART on D0/D1 to remain available for USB programming and debugging. Timing and throughput are more limited than hardware UART.

7. Pairing works but the Arduino receives nothing. How do you debug?

Confirm the app is connected to a Bluetooth Classic serial service, verify HC-05 TXD goes to the Arduino RX pin, check common ground and baud rate, and test with a minimal echo sketch.

8. Can an iPhone connect to every HC-05?

Not necessarily. HC-05 generally uses Bluetooth Classic serial profiles that are not universally available to standard iOS apps. Device, OS, module firmware and app support must be checked.

9. What is AT-command mode?

A configuration mode used on supported HC-05 firmware to inspect or change settings such as name, role, PIN or UART parameters. Entry procedure and baud rate depend on the board/firmware; follow its documentation.

10. What design precautions matter in a real product?

Check logic-level compatibility, supply stability, pairing/security behavior, radio range, latency, reconnection handling, data framing, error detection, and whether Bluetooth Classic is permitted by the target platform and requirements.

11. Is Bluetooth data automatically encrypted and secure enough for every application?

No wireless link should be assumed secure solely because it is paired. Assess the module's security capabilities, pairing configuration, firmware age, threat model and the sensitivity of the commands/data.

12. Why might SoftwareSerial lose bytes?

Software-based serial depends on precise timing and can be disrupted by interrupts or high data rates. Reduce the baud rate, minimize other timing-critical work, or use a hardware UART when reliability/throughput matters.

11. Quick revision sheet

Important facts

  • HC-05 commonly provides Bluetooth Classic ↔ UART connectivity.
  • TXD connects to the other device's RX; RXD connects to the other device's TX.
  • Use common ground between Arduino and module.
  • Protect the HC-05 RXD input from 5 V logic; verify exact board ratings.
  • 9600 baud is common in data-mode examples, but configuration may differ.
  • Pairing is not the same as a live serial-terminal connection: connect to the module from a compatible app.

Final lab conclusion

The HC-05 enables short-range wireless serial communication between an Arduino and a compatible Bluetooth Classic device. Correct TX/RX wiring, common ground, appropriate supply voltage, safe logic levels, and matching UART settings are the main requirements for reliable operation.

Assumptions and limitations: The circuit and code target a typical Arduino Uno plus HC-05 breakout board. Breakout designs, pin labels, firmware, pairing PINs, and default baud rates vary.
